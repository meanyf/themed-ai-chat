# Кулинарный помощник

Одностраничный чат с Gemini о рецептах, продуктах и способах приготовления. После входа по общему ключу открывается одна лента для всех участников. PostgreSQL хранит сообщения и время отправки, а браузер показывает время в часовом поясе пользователя.

## Запуск

Понадобятся Git, Docker с Compose и ключ Gemini API. Получить ключ можно в [Google AI Studio](https://aistudio.google.com/api-keys). В редакторе замените значение `GEMINI_API_KEY` своим ключом, сохраните `.env` и выполните последнюю команду. Для первого локального запуска можно оставить остальные значения из примера.

### Linux и macOS

```bash
git clone https://github.com/meanyf/themed-ai-chat.git
cd themed-ai-chat
cp .env.example .env
nano .env
docker compose up --build -d
```

### Windows (PowerShell)

Запустите Docker Desktop и выполните в PowerShell следующие команды.

```powershell
git clone https://github.com/meanyf/themed-ai-chat.git
cd themed-ai-chat
Copy-Item .env.example .env
notepad .env
docker compose up --build -d
```

Контейнер приложения дождётся готовности PostgreSQL, применит миграции Alembic и запустит FastAPI.

Откройте [чат на localhost:8000](http://localhost:8000) и введите значение `ACCESS_KEY` из `.env` (в примере — `local_chat_key`). Попробуйте спросить «Чем заменить яйца в оладьях?». После обновления страницы переписка останется на месте. Остановить проект можно командой `docker compose down`. История сохраняется в именованном томе `postgres_data`.

## Устройство проекта

Бэкенд следует принципам **чистой архитектуры**. Зависимости направлены внутрь: слой сценариев использует доменные сущности и определяет интерфейсы для работы с хранилищем и моделью. Домен и сценарии независимы от FastAPI, PostgreSQL и Gemini.

Например, при отправке вопроса HTTP-маршрут вызывает `ChatService`. Сервис создаёт доменное сообщение, сохраняет его через `MessageRepository` и запрашивает ответ через `LLMClient`. Реализации этих интерфейсов для PostgreSQL и Gemini подключаются в `app/main.py`, поэтому смена провайдера модели затрагивает адаптер и сборку приложения.

| Где | За что отвечает |
| --- | --- |
| `app/domain/` | Сущности сообщения и сессии. Здесь проверяются правила, в том числе предел в 500 символов для вопроса. |
| `app/services/` | Сценарии чата и авторизации. Интерфейсы в `services/interfaces/` позволяют проверять эти сценарии с подменой базы и клиента модели. |
| `app/repositories/`, `app/db/`, `migrations/` | Хранение истории и сессий в PostgreSQL 17 через SQLAlchemy, схема таблиц и миграции Alembic. |
| `app/integrations/gemini.py` | Запрос к Gemini с текущим вопросом и системным промптом. Тему можно изменить через `SYSTEM_PROMPT`. |
| `app/api/`, `app/main.py`, `app/core/config.py` | HTTP-маршруты и схемы, сборка приложения и чтение настроек. FastAPI отдаёт страницу и API с одного адреса. |
| `frontend/` | Интерфейс на HTML, CSS и JavaScript. Браузер загружает историю, отправляет вопросы и показывает состояние запроса. |

Вопрос сохраняется **до обращения к Gemini**. Если модель недоступна, вопрос остаётся в истории. При обрыве соединения интерфейс предлагает сверить ленту с сервером перед повторной отправкой.

### Авторизация

Используется **сессионная аутентификация**: общий ключ нужен один раз при входе, а доступ к истории и отправке сообщений сервер проверяет по сессии.

Браузер передаёт введённый ключ в теле `POST /api/auth/login`. Сервер сравнивает его с `ACCESS_KEY` и при успехе выдаёт случайный токен в cookie с атрибутами `HttpOnly` и `SameSite=Strict`. Браузер отправляет cookie при обращении к API. В PostgreSQL хранятся SHA-256-хеш токена и срок действия сессии — 24 часа с момента входа. При выходе сервер удаляет сессию и очищает cookie. Ключ Gemini используется только на сервере.

## Что можно доработать

- Добавить идентификатор запроса для каждого вопроса. Тогда после обрыва связи сервер сможет распознать повторную отправку даже при двух одинаковых текстах подряд.
- Загружать старые сообщения порциями при прокрутке вверх, чтобы большой диалог быстро открывался.
- Добавить ограничение частоты попыток входа по ключу доступа.
